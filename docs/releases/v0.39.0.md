# FourPataka v0.39.0 — contributor preview

This release provides the local Fourier instrument/composition studio and its reviewed, bundled-source extension APIs. It is a pre-release prototype for Windows x64, with browser development through Node24.

## Application

- Instrument editing: 32 signed harmonics, waveform drawing/control points, undertones, envelopes, percussion hits, library folders and independently owned A/B/track sounds.
- Compose: one saved song with named virtual files and multiple tracks per file, chord shapes and note previews, grouped articulation/tuplets, meter changes, arithmetic beat positions, repeats/sections/alternate endings, swing, completion and command reference.
- Five serial cable-routed pedals: Compressor, Overdrive, EQ, Delay and the Level contributor example. Shared live/offline factories support frozen WAV export.
- Source/output analysis: collapsed source descriptors and channel-aware live RMS/sample peak/crest, with undoable learning experiments. A/B changes preserve the musical clock.
- Browser/local persistence and native JSON/WAV workflows, recovery, undo and unavailable-module data preservation.

## Contributors

M1–M5 provide numeric metadata, pedal processors, Fourier preset factories, synthesis engines and declarative panels/experiments. GPL-3.0-only source, complete bundled dependency/runtime notices, public-boundary examples, compatibility checks, diagrams and tutorials accompany the application. The M6 follow-up adds an isolated first-contribution exercise, private reporting, branch checks and durable binary/source distribution. It does not change musical behavior or bump the application version.

Follow CONTRIBUTING.md and docs/extensions/CONTRIBUTOR_WALKTHROUGH.md in the source archive or repository. There is no runtime plugin installer: source contributions are reviewed and explicitly registered before building. Project data never loads executable modules.

## Downloads and source

Download the Windows x64 portable executable and the **attached exact corresponding source ZIP** together with BUILDING.txt and SHA256SUMS.txt. The release tag identifies the CI-tested source commit; the source ZIP filename includes its full commit. The GitHub-generated tag ZIP is also available, but the attached archive is the one explicitly checked before publication.

Extract the source, install Node24, and run `npm ci` then `npm run build`. On Windows, `npm run desktop:package` prepares the pinned Electron runtime and builds the portable. No Visual Studio is required. Source/lockfile/scripts/assets and license notices are included; dependencies and the official Electron runtime require downloads. Rebuilding is supported; bit-for-bit binary reproducibility is not claimed. Git-dependent maintenance commands require a clone rather than an extracted source archive.

## Verified scope and limits

Contributor CI checks source formatting/notices/private-file exclusion, units, production build, knowledge freshness, Chromium integration, the isolated tutorial and Windows packaged/native workflows. The release is published only after both required jobs pass for its tagged commit. M6 evidence and actual run links are recorded in IMPLEMENTATION_STATUS.md.

The portable is **unsigned** and uses a default icon. Windows may show an unknown-publisher prompt. macOS/Linux native packages, other browsers/devices, physical listening and screen-reader behavior are not verified support targets. CPU/node/memory preflight estimates are not measured device guarantees. Source descriptors exclude percussion noise/envelopes; live levels are sample-based, not true-peak or LUFS.

Phaser/chorus/reverb, instrument-chamber acoustics, WAV-to-instrument reconstruction, advanced phase/partial envelopes, runtime loading and a marketplace remain future work. Report security issues privately through the repository Security tab; see SECURITY.md. Release assets and their matching source stay together; replace neither silently after publication.

The checked release identity, source-file comparison policy, CI run and all four asset sizes/SHA256 values are retained in [the publication attestation](v0.39.0-assets.json).
