# Score workspace follow-ups

Status: planned on 2026-10-06. Track tabs are the next application milestone; variable swing is a later composition feature. Neither is available in v0.23.1. These milestones do not complete the modularity program or remaining physical listening/device/screen-reader gates.

## Shared-file track tabs

1. **Source adapter.** Build a revision-aware index of complete track blocks and shared directives. Reuse lexer/parser spans; nested repeat braces and articulation/tuplet brackets cannot terminate a track view early. Patch canonical scoreText only against its current revision. Preserve text outside the patch byte-for-byte, including CRLF, comments and directive ordering. Fall back to All score when a block cannot safely be indexed; explain the diagnostic instead of guessing an edit destination.
2. **Editor views.** Show All score and one named tab per actual track. A track view contains its header/body, so instrument and pedal assignments stay actual score syntax. Use the full view for shared tempo/time/master directives; indicate that they apply to every track. Store per-view cursor/scroll state separately from musical history. A visual melody or bass tab is never a physical melody/bass file or a second authoritative source buffer.
3. **Track operations.** New tab creates a valid track with a unique key and explicit instrument assignment; rename/remove change the actual block as a grouped undoable operation. Preserve owned sound/pedal copies with existing reconciliation rules and require collision-free keys. Decide how a rename transfers an owned copy before coding it; visual focus alone must never reassign another track's settings.
4. **Integrated IDE.** Translate local edits, diagnostics, chord hover, completion, command insertion and playback highlights to canonical source offsets. Undo/redo spans the entire score and restores a useful view even after tab deletion. Compiling a tab alone must never mute hidden tracks: Play, comparison and WAV use one whole-score snapshot. Edits become audible on replay, preserving the playing clock and A/B phase.
5. **Verification and contributor notes.** Cover malformed/duplicate blocks, arbitrary directive placement, CRLF/comments, nested groups/repeats, stale revisions, external full-score edits, cross-tab history and one-file autosave/import/export/native saving. Test all tracks together in browser/native playback and WAV, keyboard tab selection/rename controls, narrow layouts and portable startup. Explain the source-view service boundary for later M5 extensions; keep the API explicitly provisional until that contract lands.

Default view and exact new-tab controls can be refined during implementation. The canonical single-file invariant is required. The existing full-score editor stays available for recovery and shared settings.

## Variable swing

Use a timing proof first, then parser/reference controls, then playback/export verification. Keep each stage separately reviewable.

- **Amount and units.** Proposed amount is the long subdivision's share of a pair: 50% gives equal durations; 66.7% approaches 2:1. Validate a practical initial range, such as 50–75%, in the timing proof. Zero effect must reproduce today's timing exactly. Eighth/sixteenth subdivision selection is independent of tempo. Draft notation and default/global versus per-track scoping remain design choices, not implemented syntax.
- **One performance map.** Retain rational written beat positions for meter, repeats, diagnostics and editing. Derive sounding onset/end positions from a bounded monotonic pair warp anchored to quarter-note boundaries (eighth pairs) or half-quarter boundaries (sixteenth pairs). Pair endpoints stay fixed, so swing does not accumulate drift or lengthen a bar. Compute gate/legato behavior from performed intervals rather than applying another timing scale inside each voice factory.
- **Explicit edge policies.** Proposed default: chords share one onset; notes/rests participate in the same grid warp; explicit tuplets retain their written ratio rather than receive a second swing warp. Decide and test crossings into/out of tuplets and dotted/long notes. Leave incomplete pairs at meter boundaries straight, including odd eighth-note bars; prevent any warped onset from crossing the next meter boundary or reversing event order. Specify how track end and repeat boundaries interact with the pair grid rather than resetting swing by accident on each pass.
- **Shared rendering and clocks.** Live playback, WAV export and comparison consume the same performance map; transport elapsed time and source highlighting follow actual playback, while the written timeline retains its editing grid and clearly exposes performed timing. Freeze swing with the playing revision. A/B changes timbre at the current phase/clock without recomputing or restarting the groove. Preserve look-ahead/latency compensation, independent copies, bounded tails and hard Stop cleanup.
- **Acceptance.** Unit-check straight identity, ratio values, fixed pair endpoints, monotonic ordering and long-score drift, odd/compound meters and changes, rests/chords/dots/nested tuplets/repeats, articulation and track overrides. Compare scheduled live/WAV event times and output, then verify editing/undo/save/reload, reference/completion, comparison continuity, native packaging and manual listening. Unknown/invalid swing syntax must diagnose without silently substituting a groove. Resource and compatibility limits remain visible.
