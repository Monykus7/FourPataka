# Score workspace follow-ups

## Virtual song filesystem — implemented v0.28.0

Named file tabs above the Compose IDE use `from song <key>` and share one canonical scoreText/project JSON. Each file supports several tracks. Matching keys continue in source order with shared sections and owned sounds; distinct tracks start in parallel. Create/rename/delete are source/history operations; closing keeps music and selection is presentation-only. Open/active state persists through save/open/recovery. Track Maker and commands target the selected file. All files retains boundary recovery. See [virtual song files](extensions/SCORE_FILES.md) for services, syntax, limits and diagrams. Variable swing is implemented in v0.38.0; M1–M5 contracts are implemented and remaining M6 gates stay separate.

Status: track tabs are implemented in v0.24.0 (2026-10-10). Named sections and alternate endings are implemented in v0.27.0 (2026-10-11); variable swing remains a planned later feature. Their implementation gates remain separate. These milestones do not complete the modularity program or remaining physical listening/device/screen-reader gates.

## Shared-file track tabs

1. **Source adapter.** Build a revision-aware index of complete track blocks and shared directives. Reuse lexer/parser spans; nested repeat braces and articulation/tuplet brackets cannot terminate a track view early. Patch canonical scoreText only against its current revision. Preserve text outside the patch byte-for-byte, including CRLF, comments and directive ordering. Fall back to All score when a block cannot safely be indexed; explain the diagnostic instead of guessing an edit destination.
2. **Editor views.** Show All score and one named tab per actual track. A track view contains its header/body, so instrument and pedal assignments stay actual score syntax. Use the full view for shared tempo/time/master directives; indicate that they apply to every track. Store per-view cursor/scroll state separately from musical history. A visual melody or bass tab is never a physical melody/bass file or a second authoritative source buffer.
3. **Track operations.** New tab creates a valid track with a unique key and explicit instrument assignment; rename/remove change the actual block as a grouped undoable operation. Preserve owned sound/pedal copies with existing reconciliation rules and require collision-free keys. Decide how a rename transfers an owned copy before coding it; visual focus alone must never reassign another track's settings.
4. **Integrated IDE.** Translate local edits, diagnostics, chord hover, completion, command insertion and playback highlights to canonical source offsets. Undo/redo spans the entire score and restores a useful view even after tab deletion. Compiling a tab alone must never mute hidden tracks: Play, comparison and WAV use one whole-score snapshot. Edits become audible on replay, preserving the playing clock and A/B phase.
5. **Verification and contributor notes.** Cover malformed/duplicate blocks, arbitrary directive placement, CRLF/comments, nested groups/repeats, stale revisions, external full-score edits, cross-tab history and one-file autosave/import/export/native saving. Test all tracks together in browser/native playback and WAV, keyboard tab selection/rename controls, narrow layouts and portable startup. Explain the source-view service boundary for later M5 extensions; keep the API explicitly provisional until that contract lands.

The implemented default is All score. New track tab writes a real instrument-assigned block with rest bar; Rename preserves owned sound/chain state, and Remove is confirmed/undoable. Duplicate/incomplete source structure switches to All score, retaining edits. Cursor/scroll are remembered during Compose view switches; source/save/export stay canonical and schema2 stays unchanged. See [current services and diagrams](extensions/SCORE_VIEWS.md) and IMPLEMENTATION_STATUS.md for actual validation. The numbered phases above describe the required architecture rather than an unimplemented tab proposal.

## Named sections and alternate endings

Requested on 2026-10-06 as a separate milestone extending the shared-file Compose tabs. Dependency: the track-tab source adapter and whole-score view services. Keep section definitions and references in the same canonical score file, with per-track section navigation inside the existing virtual track views. Labels such as A, B, verse and chorus are source-owned names, not separate files or copies of the music.

1. **Section language and index.** Define a block of existing music without playing it; explicit play calls perform it at their written positions in the same track. A and B may each exist in melody and bass without colliding; cross-track reference/copying is out of the first release. Retain definition and call-site spans so diagnostics/hover/navigation can show both. Validate unique names, missing references, self/mutual cycles, resource limits and malformed blocks. Forward references are supported; do not treat a missing definition as silence. Preserve current anonymous repeat syntax and existing saved scores without automatic rewriting.
2. **Repeat and tail trimming.** Reusing a label expands the original section body at the call's current beat; enclosing repeat blocks may reuse it multiple times. Allow a reuse to omit its final n quarter-note beats and supply a different ending. Use the existing bounded arithmetic/fraction conventions: n=0 is identity, fractional cuts are allowed, negative values or cuts longer than the resolved section diagnose. Resolve position-dependent bar rests on each invocation before measuring/cutting; never measure by bars, token count or number of notes.
3. **Boundary semantics.** Remove events wholly after the cutoff and shorten a note/chord/rest spanning it exactly to the cutoff, retaining pitches and source provenance without a new attack. Recompute gate/release and legato connections for the shortened performed interval; do not let a tail or overlap leak into the replacement accidentally. Compile the new ending sequentially after the retained prefix. Its duration may differ from the removed tail, so invocation length becomes section length minus n plus ending length; show that length and preserve normal parallel-track alignment without implicit padding. Global tempo/meter/master directives remain outside reusable track sections.
4. **Compose views.** Provide source-derived section labels/navigation within each track tab, an outline/hover showing resolved duration and origin, and clear canonical diagnostics at definition/use sites. Insert/rename/delete/reference/ending edits are grouped, undoable source operations; renaming must update only actual references in the same scope, not comments or another track's A section. Retain a full-score recovery view on invalid source. No hidden music buffer, independent instrument/pedal assignment or separate save artifact is created.
5. **Acceptance and contributor documentation.** Verify repeated references and alternate endings, same labels on different tracks, source offsets/CRLF/comments, undo/redo and one-file save/reload/import/native export. Cover exact/fractional/mid-event cuts, zero/full/invalid cuts, dotted notes, nested tuplets/repeats/articulation, position-dependent rests and meter changes; show actual expanded durations. Bound recursive expansion and compilation work. Compare live/WAV timing and source highlighting, frozen playing revisions and A/B phase/clock continuity, finite tails/hard Stop, keyboard/narrow layouts and packaged startup. Publish section syntax and a tested example through the shared command metadata and later M5 source services, without claiming a general plugin API exists today.

Implemented v0.27.0: `section A {` declares a passage without events/time, `play A` performs it, and `play A trim 2 {` adds an invocation-local ending at an exact cutoff. Each header occupies its own line. The section selector navigates/renames source; contextual reference cards and IDE completion choose local names. Chord previews include declarations and trimmed notes, while diagnostics/events retain definition/call provenance. Unused definitions validate in scratch tracks at beat zero; real calls recompile at their performed position. The [current syntax and contributor diagrams](extensions/NAMED_SECTIONS.md) describe resource bounds, actual exports and proof. No project schema change or general M5 registry is introduced. Eight focused commits and a verified portable release are recorded in IMPLEMENTATION_STATUS.md; manual release gates remain separate.

[Performance timing](extensions/PERFORMANCE_TIMING.md) documents actual syntax,50–75percent bounds, global/track scopes, incomplete-pair/tuplet policies, shared live/comparison/WAV timing and contributor diagrams.
